# Dashboard Quick Start (Member D)

## Recommended: history metrics and live curves on one page

After a Git clone, run `git lfs install` and `git lfs pull` once to retrieve the
databases and complete event stream. This is not required again for later runs.

Double-click `Start_Dashboard.cmd` in the project root. The dashboard opens at
http://127.0.0.1:8050.

The program reads C's `A2/data/final/ev_chargers_a2.duckdb` and automatically
creates an isolated working copy. The same page shows historical metrics,
station details, and live charging activity published through MQTT from A's
generated events. It does not use the retired hand-written test database and
does not modify C's formal database.

Steps:

1. The initial state shows 414 stations, 5,081 completed sessions, and 0 active sessions.
2. Click **Run demo** in the upper-right corner. The replay takes about 45 seconds.
3. Three charging-station buttons appear below the map. Select a button to view that station's live curve.
4. After replay, the totals are 5,084 completed sessions, 129,422.20 kWh, AUD 88,908.69, and 0 active sessions.
5. Click **Reset demo** to restore the initial 5,081-session history and run the demonstration again.

To inspect another station, select its marker on the map; running the demo first
is not required. A station with an active session defaults to **LIVE**. Otherwise,
the dashboard displays its most recent completed charge as **COMPLETED**, with
the description `Historical session`. Use the Session list to select an older
record. A manually selected session remains selected while the page refreshes.
After switching stations, the dashboard again prioritises that station's active
session. `Start_Dashboard.cmd` is the only required launcher.

Why does the initial count show 5,081 rather than 5,084? C's formal database
already contains A's complete dataset. To avoid double-counting during the
demonstration, the program temporarily removes three completed sessions from
the private working copy, then restores them through real MQTT messages. The
87 events are copied unchanged from A's full event stream: 3 price events,
3 session starts, 78 meter readings, and 3 session ends. Event IDs, timestamps,
sequence numbers, and values are not rewritten, and no charging record is
invented. This is a replay baseline for three selected sessions, not a snapshot
of the whole system at a historical instant. The page explains the withheld
count and the completed-session totals before and after replay.

The replay stations are `ST6DC062AC32`, `ST1A14ED4000`, and `STFFE05F9F25`.
They show live curves during replay. Other stations show the historical curves
stored in C's database. Historical curves do not continue to grow and must not
be interpreted as current charging. If the selected database contains no
session for a station, the page reports `No recorded session`; it does not
invent a curve.

The first run requires Python 3.11, 3.12, or 3.13. The launcher creates `.venv`
and installs the required dependencies when necessary. If an older dashboard
terminal is still running, close it before launching again. Refreshing the
browser does not restart the old Python process.

## Standalone live-curve demonstration

To run A's earlier single-session demonstration, execute this command from a
PowerShell terminal in the project root:

```powershell
.venv\Scripts\python.exe A2/src/dashboard/run.py --project-root . --mode demo --port 8051 --open-browser
```

Click **Run demo** and wait about 35 seconds. This mode creates a private copy
of the empty-event seed built from C's schema and reference data, then replays
36 original events generated by A. It contains no hand-written charging data
and never writes to the formal database.

The final state contains 1 completed session, 22.60 kWh, AUD 16.72, and a curve
with 32 meter points. **Reset demo** clears only the private replay copy; it
cannot clear the formal database. See `A_DATA_RUN_GUIDE.md` for details.

## Files and validation

- Recommended launcher: `Start_Dashboard.cmd`, unified history and live view on port 8050.
- Unified replay input: A's `A2/data/events/event_stream.jsonl`.
- Full read-only history: run `.venv\Scripts\python.exe A2/src/dashboard/run.py --project-root . --mode history --port 8052 --open-browser` to display all 5,084 historical sessions.
- Single-session teaching demo: use the `--mode demo` command above with A's 36-event sample.
- Optional empty-event seed: `A2/data/demo/a_generated_empty.duckdb`, created by C's initialisation code.
- English report: `A2/docs/member_d_report.pdf` and `A2/docs/member_d_report.md`.
- Unified-entry validation: `A2/data/quality/d_unified_validation.json`.
- Replay provenance: `A2/data/runtime/<run-id>/replay_provenance.json`.
- D's tests use A's generated events and do not depend on the retired hand-written test database.
- `test_station_history_dashboard.py` verifies that all 414 stations in C's formal database can load their own historical curves.

The retired hand-written database and its development screenshots are excluded
from the delivery. The original A1 database and formal A2 database remain unchanged.
