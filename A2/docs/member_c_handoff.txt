3. Contract for Member B
------------------------

Database creation must happen first:

  python A2/run_pipeline.py --stage database

Create the repository with the formal A2 database path:

  A2/data/final/ev_chargers_a2.duckdb

Expected event flow:

  MQTT callback
    -> B validates topic and JSON/event transition
    -> C store_event(topic, event)
    -> if store_event returns True: B applies the event to StateStore
    -> if store_event returns False: B ignores the duplicate

store_event() behaviour:

- Returns True when a new event is committed successfully.
- Returns False when event_id already exists.
- Raises an exception when the topic, session relationship, chronology or
  normalised data is invalid.
- Stores mqtt_events and the normalised table change in one transaction.
- Rolls back the raw mqtt_events row if normalisation fails.

Important B integration rules:

- Topic must be exactly:

    comp5339/ev/{station_id}/{event_type}

- Do not update StateStore before store_event() returns True.
- Do not create SQL inside src/subscription.
- Meter timestamps must strictly increase within a session.
- Meter energy and SoC must not regress.
- A session_end must use the price locked by session_start.
- A session must have meter telemetry before it can end.
- Same-connector sessions can hand over in the same second. Always identify the
  session being ended by session_id rather than deleting by connector alone.
- Call repository.close() when the subscriber/runtime stops.

Thread/process note:

EventRepository serialises access to its DuckDB connection with a lock. The
subscriber and dashboard runtime should share the intended repository instance
inside the owning process. Do not run the standalone subscriber and dashboard
against the same writable database at the same time.


4. Contract for Member D
------------------------

get_dashboard_stations()

Returns one dictionary per mapped station, ordered by station_id, with:

  station_id
  representative_charger_id
  station_name
  address
  latitude
  longitude
  postcode
  sa4_name
  operator_names
  plug_types
  connector_count
  charger_count
  max_rating_kw

get_latest_prices()

Returns one dictionary per station that has received a price event:

  event_id
  station_id
  event_time
  price_per_kwh
  wholesale_per_kwh
  currency

get_active_sessions()

Returns active sessions with their latest meter sample:

  session_id
  station_id
  connector_id
  start_time
  site_type
  vehicle_model
  price_per_kwh
  latest_meter_time
  voltage_v
  current_a
  power_kw
  energy_kwh
  soc_pct

Sessions without a meter sample have NULL meter fields.

get_session_meter_events(session_id)

Returns the full curve ordered by event_time and event_id:

  event_id
  session_id
  station_id
  connector_id
  event_time
  voltage_v
  current_a
  power_kw
  energy_kwh
  soc_pct

An unknown session_id returns an empty list. An empty/non-string session_id is
invalid and raises ValueError.

get_current_metrics()

Returns one dictionary:

  active_session_count
  active_station_count
  current_power_kw

get_historical_metrics()

Returns one dictionary:

  completed_session_count
  serviced_station_count
  total_energy_kwh
  total_revenue_aud
  average_charge_minutes
  maximum_peak_kw

DuckDB TIMESTAMP values are returned to Python as datetime objects. D should
format them for display rather than assuming they are already JSON strings.

The dashboard process is expected to own the MQTT background loop and database
connection. Per the team contract, do not run the standalone subscriber at the
same time as the dashboard runtime.
